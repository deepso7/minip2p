# minip2p-ffi-core

`minip2p-ffi-core` is the binding-agnostic embedding layer for minip2p. It owns the detached endpoint driver, lifecycle, flattened event model, and bounded event carry shared by foreign-language bindings.

Bindings register an [`EventDoorbell`](https://docs.rs/minip2p-ffi-core/latest/minip2p_ffi_core/trait.EventDoorbell.html) when starting an endpoint. The core rings it only when the carry changes from empty to non-empty. Bindings then call `P2pEndpoint::drain_events` synchronously until it returns an empty batch. Stream events (ready, data, write settlement, stop, remote close, close) and connection ends are never dropped, and adjacent data for one stream coalesces into one event; the receive budgets bound them (ADR 0012). Past 4096 other events the carry discards gossipsub messages first, then the oldest other event, and reports loss with `P2pEvent::EventsDropped`.

Every protocol registered through this crate, in `EndpointConfig::protocols` or with `add_protocol`, takes manual acknowledgement: a stream delivers at most one receive window the binding has not acknowledged, and the binding calls `P2pEndpoint::stream_consumed` as its reader consumes bytes. A reader that stops consuming stalls its sender instead of buffering without bound.

`P2pEndpoint::send_stream` returns `true` when the stream accepted the whole payload. When it accepted only part, ffi-core holds the one unsent tail for that stream, resends it on the stream's Writable, and emits `P2pEvent::StreamWriteAccepted` once every byte is accepted; it returns `false` meanwhile, and the stream refuses another write until then. `close_stream_write` sends its FIN only after that tail, and writes after the close request are refused. `P2pEvent::StreamWriteStopped`, `StreamClosed`, or the connection ending drop the tail instead, which tells the binding to fail its pending write.

Connection attempts follow one contract: `connect(target)` admits an attempt under a single Connect ID and the event stream carries exactly one terminal for it — `PathEstablished`, `ConnectFailed`, or `ConnectCancelled` after `cancel_connect`. If the carry drops a terminal, `EventsDropped::terminal_connect_ids` names its Connect ID so a foreign wait settles with a delivery-loss error and recovers through the State getters (`connected_peers`, `connection_info`, `path`, `known_peers`, `listen_addrs`). The detached driver owns the endpoint's wait outcomes — event, deadline, interrupted — and releases ownership on interruption so commands never deadlock. It sets no polling cadence of its own: the endpoint wait already wakes for every timer its transports, protocols, and agents report, and every command, query, and `stop` interrupts it, so an idle single-transport endpoint sleeps until something is due (a QUIC plus TCP endpoint still alternates short per-transport waits). `set_active` is accepted for compatibility and has no effect.

The optional `uniffi` feature (off by default) derives the UniFFI record, enum and error metadata on the config, event and error types, making this crate its own UniFFI namespace for the `minip2p-ffi` shell. Other shells build without UniFFI. The optional `serde` feature (also off by default) derives `serde::Serialize` with the JavaScript-facing shape that the napi-rs shell (`minip2p-nodejs`) and the TypeScript SDK share; the crate's `js_shape` module documents and tests it.

Listening is address-shaped: `EndpointConfig::listen` takes multiaddresses whose shape selects QUIC or TCP. Leaving it `None` binds the QUIC dual-stack defaults; an explicit empty list is rejected.

The crate is an internal workspace component and is not published.
