# minip2p-relay-server

`minip2p-relay-server` is the deterministic `no_std + alloc` policy layer for hosting a Circuit Relay v2 server. The relay wire crate owns one HOP or STOP handshake; this crate owns the whole service: reservations, exact-connection identity, admission, token buckets, control deadlines, circuits, forwarding, accepted-byte accounting, and typed lifecycle events. Sockets, system clocks, blocking waits, Endpoint composition, ACLs, discovery, metrics, and proxy-aware IP policy stay in adapters.

The host passes a `Now` and a `RelaySwarm` into every `handle_event` and `handle_tick` call; `SwarmCore` implements `RelaySwarm`, and `mesh::MeshSwarm` joins a mesh node's two swarms into one. The agent never stores the swarm. It opens, writes, acknowledges, half-closes and resets inline and applies each result before the call returns, so a reservation or circuit commits as soon as the transport takes its success reply. The agent acknowledges the stream data it claims itself, so the host must not.

```rust,ignore
let claimed = agent.handle_event(&mut swarm, &event, event_is_on_a_circuit, now);
while let Some(event) = agent.poll_event() { /* reservations, circuits, diagnostics */ }
```

Only the STOP open completes later. `open_stream` returns the stream at once; the agent checks it is on the reservation's exact connection, then settles it from the stream's `StreamReady`, its `StreamClosed`, or the `SwarmEvent::Error` naming it. A swarm cannot reset a stream still negotiating, so a STOP stream the relay gives up early (its circuit timed out, or the source left) is reset at its late `StreamReady`; the relay claims a given-up STOP stream's events until it closes.

The first `handle_event` at each `Now` sample processes due deadlines before dispatching that event, so deadlines win at equality: STOP readiness or acceptance at its circuit's deadline finds the circuit timed out. Call `handle_tick(swarm, now)` to force that sweep without an event. The service assumes Swarm's single live connection per peer but keeps exact connection and stream identities so stale inputs from a replaced connection cannot mutate replacement state. Pass `is_circuit` for the event's connection (for `ConnectionReplaced`, the `new` one); the agent reads each new connection's remote address from the swarm.

Admission, cancellation, connection close, `next_deadline`, and a tick with nothing due are indexed by connection, peer, stream, and deadline, so their cost does not grow with unrelated reservations or circuits. The `relay_server_event_ir` bench runs each case at 100, 1k, and 10k reservations and circuits to show it.

## Relay mesh

Several relay processes can serve one public relay identity (see `docs/plans/relay-mesh.md`). Set `RelayServerConfig::mesh` to a `mesh::MeshConfig` naming the other nodes' backbone peer IDs, and the agent becomes a mesh node. With `mesh: None` (the default) nothing changes.

The host runs a second swarm for the backbone, under the node's own backbone identity, with QUIC connection IDs in the `MESH_IPV4`/`MESH_IPV6` namespaces; `mesh::register_backbone_roles` installs its protocols. Feed both swarms' events to the one agent (`is_circuit = false` for backbone events) and pass a `mesh::MeshSwarm` joining the two swarms, which routes mesh-protocol opens to the backbone and every other command by its connection's namespace. A mesh node needs `Now::unix_seconds`: reservation expiries cross the backbone as UNIX seconds.

- **Membership.** A backbone connection from a peer not in `members` is closed as it is established (`RelaySwarm::close_connection`), and directory or forward streams from anyone but a member's current link are reset.
- **Directory.** The node opens one `/minip2p/relay-mesh/directory/1.0.0` stream to each connected member and sends a `Present` for every local reservation, then `Synced`; after that it sends `Present` on every commit, renewal, and move to a replacement connection, and `Gone` when a reservation ends. A directory stream that ends while its link is up reopens after 1 s, doubling to 30 s, reset once a snapshot is out; `next_deadline` includes that timer. What members send is kept in a `mesh::Directory`: a member's entries go when its stream ends or its link drops, and a malformed or over-cap stream (`max_directory_entries_per_member`, 4,096 by default) is reset.
- **Resolving a CONNECT.** The entry node runs all of today's admission checks and spends the rate token. Then a local reservation wins; otherwise it forwards to the claim with the latest expiry (ties by lower backbone peer ID), and on `NO_RESERVATION`, `CONNECTION_FAILED` or a failed link tries the next. With no claim left but a member still unsynced, the CONNECT waits for that member's `Synced` or link drop. At the end, or at the CONNECT's control deadline (`control_stream_timeout_ms`, shared across claims), the dialer gets the last refusal seen, `NO_RESERVATION` if none, or `CONNECTION_FAILED` if a forward was still pending. A holding node's `RESOURCE_LIMIT_EXCEEDED` or `PERMISSION_DENIED` is passed on as is. Clients never need to retry.
- **Forwarding.** The entry node opens `/minip2p/relay-mesh/forward/1.0.0` to the holding member and sends `Forward { source, destination, limit }`. The holding node answers `NO_RESERVATION` first if it has no live reservation for the destination, then applies pause, the global circuit cap, the destination's per-peer and per-IP caps and its connection's pending-STOP cap (no rate token, no source IP key), opens STOP with the forwarded source and limit, and replies with one `Status`. After `OK` both nodes splice bytes as for a local circuit, with the same backpressure, half-close and reset handling; dialer bytes sent early are buffered up to 64 KiB. Both nodes enforce the entry node's limit, which each circuit stores. `CircuitOpened` and `CircuitClosed` carry `via: Some(<other node's backbone peer ID>)` for a forwarded circuit.

The `mesh` module also exports the wire codec (`DirectoryMessage`, `ForwardMessage`, length-prefixed protobuf frames capped at 8 KiB like relay control frames).

## Compatibility contract

| Area | Behavior | Classification |
| --- | --- | --- |
| Reservation cardinality/renewal | One committed reservation per peer; only the exact stored connection renews it. This relies on Swarm's single-live-connection-per-peer invariant for exact STOP targeting. | Deliberate minip2p deviation from rust-libp2p's connection cardinality. |
| Connection replacement | On `ConnectionReplaced`, a reservation moves to a direct `new` connection with its original expiry (rate-limit history is neither moved nor refunded) and closes with `ConnectionClosed` if `new` is a relay circuit. Uncommitted RESERVE exchanges on `old` are cancelled; pending and active circuits on `old` fail or close with `CircuitCloseReason::ConnectionClosed { leg }`. | Deliberate minip2p behavior. |
| Admission key | Per-IP limits key on the remote address's first IP: an IPv4 address (IPv4-mapped IPv6 included) or an IPv6 /64. A connection without an IP has no key and skips per-IP limits. A reservation or circuit keeps the key it was admitted under. | Deliberate minip2p deviation: rust-libp2p keys on the exact IP (ADR 0018). |
| Reservation admission | Availability, peer rate, IP rate, then exact capacity: 128 overall and 8 per key, counting committed reservations (a reply is written inline, so none waits on its result). A rate-limit token is spent only by a request every check admits, so a full relay does not drain a waiting peer's tokens. Renewals spend no rate token and replace their slot, including at capacity. A renewal whose reply fails keeps its reservation and old deadline. Each `ReservationDenied` carries a local `ReservationDenialReason` (`Paused`, `OverCircuit`, `RateLimited`, `ReservationLimit`, `ResponseNotEncodable`); its `status()` is what goes on the wire. | Deliberate minip2p deviation: tokens charged only on admission, and corrected exact capacity. |
| Circuit admission | 16 overall; 4 per peer and 8 per key, each counting pending and committed circuits at either end, and a circuit once when both ends share the peer or key. A CONNECT spends its rate-limit tokens only when admitted. Every limit refusal is `RESOURCE_LIMIT_EXCEEDED`. | Deliberate minip2p deviation from rust-libp2p's source-only peer cap; the per-key cap is a minip2p extension. |
| Limiters | Four fixed optional full-starting token buckets, each configured as capacity plus one-token refill interval. Each limiter tracks at most `max_rate_limit_entries` keys (1,024): fully refilled buckets are dropped first, and when the map is still full a new key is refused rather than evicting a depleted bucket and handing back its burst. | rust-libp2p parity in defaults/algorithm; fixed public shape and the entry cap are minip2p extensions. |
| Static HOP, NAT, pause | Relay enablement advertises HOP statically; NAT is outbound-HOP-only. Pause denies new work but preserves HOP and existing lifecycles. Circuit HOP negotiates then returns `PERMISSION_DENIED`. | Deliberate minip2p deviations from dynamic upstream HOP plus a minip2p control extension. |
| Address selection | Explicit trusted override, AutoNAT-confirmed direct addresses, then concrete listeners; first non-empty source, filtering, first-wins deduplication, deterministic truncation. A rejected `set_listener_addrs`/`set_confirmed_addrs` refresh keeps that source's previous addresses and queues `AddrsRejected { source, error }` when the source starts failing or its error changes; its next accepted refresh queues `AddrsRestored { source }`. With every source empty (say, only a `0.0.0.0` or `::` listener, no announce addresses and no AutoNAT-confirmed address), RESERVE is still granted, with an empty `addrs` list: clients build circuit addresses from the address they dialed the relay at. rust-libp2p's relay client (as of the pinned interop revision) rejects such a reply as a protocol violation (`NoAddressesInReservation`), so give the relay an announce address when it serves rust-libp2p clients. Wildcards are never advertised or expanded. | minip2p extension/deviation from rust-libp2p's confirmed-address source. |
| Identify updates | Selection changes affect future Identify exchanges only; no Identify Push or forced re-identification. | Deliberate minip2p behavior. |
| Frames and malformed input | 8 KiB control frames; deterministic specified status/reset handling. | minip2p extension; rust-libp2p uses 4 KiB and drops some malformed HOP input. |
| Byte accounting | Per-direction transport-accepted totals include pipelined payload and every accepted prefix of a partially accepted chunk. Equality remains open; the accepted bytes that cross the limit are delivered and counted, then the circuit closes. | Circuit Relay v2 parity in directionality; minip2p extension versus rust-libp2p aggregate/excluded pipelining. |
| Duration and zero limits | Duration starts at committed HOP success, including pipelined work. Zero duration/bytes are unlimited and advertised as zero. | Circuit Relay v2 parity; deliberate deviation from rust-libp2p's zero/immediate and later start. |
| Lifecycles | Exactly-once typed reservation/circuit events, terminal reasons, and directional totals commit only after transport acceptance. Unix expiry is optional; monotonic time governs lifetime. | minip2p extension. |
| Control caps and timing | Separate post-negotiation HOP/STOP caps and end-to-end deadlines; no Swarm-wide pre-negotiation cap. | rust-libp2p-shaped workers with deliberate end-to-end minip2p timing. |
| Forwarding/backpressure | Each direction keeps an in-order queue, bounded by the receive budget granted to its sender; small reads are coalesced so its memory tracks its bytes, not its reads. Source bytes are acknowledged only once the destination accepts them; a `Full` send keeps its unsent tail at the head and resends it on the destination's `StreamWritable`, so a full destination pauses the source instead of closing the circuit (ADR 0012). A half-close is forwarded after the last queued byte. A `Full` control message (HOP or STOP) still fails like any rejected send, and its stream is reset rather than half-closed, so a truncated reply never ends in a clean FIN. | minip2p extension. |
| Reservation voucher | `voucher: None`. | rust-libp2p parity, while deliberately omitting the protocol recommendation. |

These choices deliberately correct or differ from rust-libp2p 0.22 where the canonical minip2p relay-server specification says so.

## Explicit non-goals

The service does not provide reservation vouchers, relay discovery/autorelay, ACLs, metrics, proxy-aware IP limiting, a portable/smoltcp Endpoint driver, Swarm-wide pre-negotiation stream caps, or replacement of existing test relay fixtures. These omissions are not claimed as Circuit Relay v2 or rust-libp2p parity. Low-level portable hosts may drive this crate directly; only the application-facing Endpoint adapter is std-only.
