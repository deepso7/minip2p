# Prebuilt distribution for @minip2p/node

`@minip2p/node` ships prebuilt `.node` binaries for seven targets (linux x64/arm64 gnu and musl, darwin x64/arm64, win32 x64) as binary-only platform packages (`@minip2p/node-<target>`) selected through `optionalDependencies` — napi-rs v3's standard pattern. The package is ESM-only, requires Node ≥ 24, is version-locked to the workspace, and fails at require-time with the supported-target list when no binary matches; `npm install` never needs a Rust toolchain.

## Considered Options

- **Per-platform `optionalDependencies` packages** (chosen): npm resolves the right binary at install with no postinstall script and no network fetch, so installs work in air-gapped CI and under pnpm's default script blocking; the esbuild/swc/biome pattern, generated by `@napi-rs/cli`.
- **Postinstall download from GitHub releases**: one package, but breaks behind proxies and pnpm ≥ 10 blocks postinstall scripts by default.
- **Fat package**: all seven binaries in one tarball (the `@minip2p/react-native` model, which is fine for two mobile targets); every Node user would download every platform.
- **Source-build fallback for unmatched platforms**: drags a Rust toolchain into `npm install` for exactly the users least equipped to have one; rejected in favor of an actionable error.

## Consequences

- Publishing splits in two: the seven binary-only platform packages publish via the napi-rs CLI (`napi prepublish`), while `@minip2p/node` itself joins the existing pack → `verify-release-packages.mjs` → install-smoke-test → publish-tgz pipeline, so the package users actually install passes the repo's release verification. Both paths use npm OIDC trusted publishing; each new package needs one-time trusted-publisher setup on npmjs.com.
- `publish.yml` builds the matrix on native runners — ubuntu/ubuntu-arm for gnu, napi-rs Docker images on those runners for musl, macos-26 for both darwin targets (x64 cross-compiled), windows-latest for win32 — and its "`@minip2p/node` must remain private" gate is replaced by lockstep/public assertions. `release.sh` bumps and registry-verifies the new manifests.
- PR CI (`bindings.yml`) builds only linux-x64 and runs the JS tests against that real binary; the weekly `bindings-native.yml` cron builds all seven targets, so breakage on the other six surfaces within a week instead of mid-release.
- Each target is a published npm package forever: the matrix grows on demand but never shrinks casually.
