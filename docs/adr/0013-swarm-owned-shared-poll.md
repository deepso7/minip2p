# One edge-triggered mio Poll, owned by the std Swarm

Each std transport used to own a `mio::Poll` and block on it itself. To wait on several transports at once, `TransportSet` blocked in a level-triggered `poll(2)` over every member's selector fd (#299), and took 10 ms turns between members wherever that wasn't possible: off unix, or when a member exposed no fd. That fallback meant ~100 idle wakeups a second and up to a slice of extra latency on Windows, and it carried `settle_interrupt`, a per-member waker fan-out and a sleep fallback for transports that couldn't wait at all (#248). We replace all of it with a single `mio::Poll` and `Waker` owned by the std `Swarm<T>`, because mio provides one readiness API on every platform it supports, Windows included.

## Decision

- **`PollSource`** (std only) has two required methods: `attach(registry, tokens, waker)` and `dispatch(event)`. `BlockingTransport` is `Transport + PollSource`. Registration is mandatory. `Swarm<T>` can only be built for a `T: BlockingTransport`, and it attaches the transport during construction. Code that doesn't want to block uses `SwarmCore`. An unattached source treats every socket as possibly ready, so `SwarmCore` users still make progress.
- **One `Waker`, two handles.** mio allows only one `Waker` per `Poll`, so the swarm hands its own to every source, and a transport with no socket calls it when input arrives. The swarm exposes two handles on that `Waker`. `wait_handle()` interrupts: it sets a flag, then wakes. `wake_handle()` only wakes, and is used for host work such as a finished DNS lookup. Interrupts that arrive before one is consumed coalesce into a single `Interrupted`. The flag is cleared only when a wait returns `Interrupted`, so an interrupt is never lost to a non-blocking poll or an early return. Nothing depends on counting interrupts.
- **Host wakeups.** A wake that isn't an interrupt, or readiness in a token space handed to a non-transport source such as mDNS, ends the wait with `PollNext::Woken`. The swarm keeps a pending `Woken` even when the same wake also produced an event or an interrupt, rather than tracking where each wake came from; an occasional extra step is harmless. The std `Endpoint` drives a `SwarmCore` through its own engine and owns a `SharedPoll` beside it; after a batch with no events it takes a pending wake and runs one more batch, which applies resolver answers and ticks mDNS. `poll_next` and `run_until` ignore it, so a host that owns other sources uses `poll_next_interruptible`.
- **Token spaces.** Each attached source gets a fixed `TokenSpace` and allocates its own tokens inside it. The prefixes are small (4 bits for swarm-level spaces: the transport's, 14 for host sources, and one whose first token is the `Waker`'s; 8 per `TransportSet` member), so they fit 32-bit targets, and splitting a space is checked. A `TransportSet` encodes the member index in those bits, so routing an event needs no lookup table. Tokens are reused after a socket is deregistered, and a stale event is just a spurious wake. Reusable tokens are kept separate from TCP's `SocketHandle`s, which are never reused.
- **Harvest on every drive.** Every std `Swarm` and `Endpoint` drive path, blocking or not, collects one bounded batch from the shared `Poll` with a zero timeout before driving the core.
- **The poll is a reusable piece.** The `Poll`, its `Waker`, the token layout and the interrupt/wake bookkeeping live in `minip2p-transport` as `SharedPoll`, and the swarm owns one. A host that holds a `SwarmCore` rather than a `Swarm` can own one beside it the same way, and transport tests use it directly instead of a wait of the transport's own.
- **Reporting order.** A wait reports, in order: an event, a pending interrupt, a pending host wake, the caller's deadline. A pending interrupt is therefore reported even by a wait whose deadline has already passed, so a host's non-blocking pump still notices it; it is never reported twice.
- **Edge-triggered contract.** mio reports readiness edges, not levels, on every platform. After `dispatch`, a source reads each ready socket until `WouldBlock`, or remembers what it hasn't read yet and reports `next_deadline() == now` until `poll` has consumed it. We reuse the existing deadline signal instead of adding a "pending input" hook.

## Rejected alternatives

- **Keep the level-triggered `poll(2)` over member fds.** #299 chose it deliberately: a member that fails to drain its socket shows up as a visible spin, not a lost wakeup. But it only works on unix, and it still needed the turn-taking fallback everywhere else. We accept the edge-triggered risk and cover it with the contract above and a test for it.
- **The `TransportSet` owns the `Poll`.** A single transport driven by `Swarm<T>` directly would then still need its own blocking path, which means two wait implementations.
- **A central token allocator with a token→member map.** It would need shared state and bookkeeping on every register and deregister. Fixed spaces need neither, at the cost of an upper bound on member count that no real setup will reach.
- **The `Endpoint` keeps its own caller-interrupt flag.** Two layers would each track whether a wake came from the caller. Separate interrupt and wake-only handles on the swarm keep that distinction in one place.
- **One `Interrupted` per interrupt call.** That would need a counter, and callers would see bursts of `Interrupted` with nothing new behind them. ffi-core already counts its pending commands separately.

## Consequences

- `readiness_fd`, `wait_for_input`, `wait_handle` on the transport trait, `WaitOutcome::Unsupported`, the swarm driver's idle-sleep fallback, `settle_interrupt`, the per-member waker list and the `Endpoint`'s `caller_interrupt` flag are all removed. The wait handle comes from whoever owns the poll (the swarm, or the `Endpoint`), and the DNS resolver uses its wake-only handle.
- mDNS registers its sockets for wakeups only, so `socket_poll_interval_ms` is removed everywhere. Its hard-failure retry delay becomes a named constant (`MDNS_FAILURE_RETRY`, 100 ms) when that retry exists; today a hard failure still ends mDNS, so #251 introduces both.
- TCP providers have no blocking seam of their own any more: a hosted provider is a `PollSource`, and `TcpTransport` forwards `attach`/`dispatch` to it. A smoltcp `MdnsIo` reports a deadline of now while a datagram is waiting, but a smoltcp host must still wake when its device receives input.
