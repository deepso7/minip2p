# Reject invalid protobuf field numbers in the shared decoder

The shared protobuf decoder (`read_tag` in `minip2p-core`) rejects field numbers outside the spec's valid range, 0 and anything above 2^29−1, with `WireError::InvalidFieldNumber`, for every protocol. This reverses the earlier rule that field-number policy stays with each caller, under which protocols disagreed: some rejected field 0 with four different errors, and identify, relay and DCUtR silently skipped it. Implementations differ upstream: go-libp2p (google.golang.org/protobuf), rust-libp2p since its move to prost, and the official Java parser reject; quick-protobuf (older rust-libp2p) and js-libp2p's protons skip. We follow the spec and the rejecting implementations because no well-behaved peer emits these numbers, so the only peers affected are malformed ones. The trade-off is stricter acceptance than skip-tolerant decoders, not a demonstrated security fix. Opaque embedded payloads (signed records, vouchers, extensions) are not recursively validated.
