# QUIC admission through memory reservations

> Partly superseded by ADR 0022: the memory budget, memory reservations and the window defaults sized for them are gone. `max_connections` across sockets, Retry, the windows as `QuicLimits` fields and the Apple fast-path exception stand.
>
> **Amended by #387**: the shared-allocation exception in Consequences is resolved. Each received datagram is copied into an allocation of its own length, so a stream chunk the engine buffers pins only its own datagram, not the rest of its receive call.

Supplements ADR 0012. ADR 0012 bounds received data per transport by connection limit × stream limit × stream window, but QUIC's numbers made that bound meaningless: `max_connections` (1024) counted per socket, so dual-stack allowed 2048, and each connection could commit an 8 MiB pending-send queue, a 10 MB engine send buffer, a 10 MB connection receive window and up to 128 peer streams of 1 MB each, about 284 MB per connection (#243). We decided:

- **One QUIC memory budget per transport.** `QuicLimits::memory_budget_bytes` (512 MiB by default, 640 MiB since #361) covers every socket of a `QuicTransport`, and `max_connections` now counts across sockets too. The budget caps the transport's worst-case queued memory.
- **Connections and streams hold memory reservations against it.** A connection reserves its fixed part at admission: twice its pending-send queue (a queued write may keep a slice of the caller's payload, and ADR 0012 bounds the allocation it pins only to twice the bytes it counts), the engine's send buffer and its connection receive window (`QuicLimits::connection_reservation_bytes`). It releases that part when it drains, because that memory is gone. A stream reserves its receive window when it opens or is admitted (`stream_reservation_bytes`) and keeps it until it settles, which for delivered bytes means acknowledged or abandoned, also after its connection ended. An unsettled connection therefore keeps its streams' reservations and its connection slot, but not its fixed part. Each socket's retry queue (`max_pending_datagrams` full-size datagrams) is reserved at bind for the transport's lifetime, because datagrams queued behind `WouldBlock` can outlive their connection.
- **What does not fit is refused, never queued.** A local dial or `open_stream` fails with `ResourceExhausted { resource: "QUIC memory budget" }`. An inbound connection from an address validated by Retry gets `CONNECTION_REFUSED`; one from an unvalidated address gets silence, as at the connection limit, so a spoofed source cannot use the refusal as a reflector. Retry runs before the budget check, so a client the budget refuses still learns why instead of timing out. An inbound stream that does not fit is refused like one over the stream limit.
- **Full and Writable stay per connection**, as ADR 0012 has them. There is no shared write pool and no per-connection receive gate: ADR 0012 rejected those, and they starve or deadlock streams. The budget only decides admission.
- **The windows are limits, sized to the budget.** The send, stream and connection windows became `QuicLimits` fields, and a budget too small for the sockets' retry queues plus one connection and one stream is `InvalidLimit`. The defaults shrink the fixed part (send window 10 MB → 2 MiB, connection window 10 MB → 3 MiB, pending queue 8 MiB → 1 MiB, chosen with the throughput bench). The queue stays well above the control reserve plus one stream's cap, so one stalled stream cannot fill the application share; the connection window stays above a few stream windows, so a few gated streams cannot spend the credit control streams need. The default budget admits at least 64 connections with a stream each, and that floor holds when the windows change: tuning the windows at a real RTT (#361) raises the default budget rather than admitting fewer connections.
- **Hosts size the budget from their own limits.** The relay binary derives its budget from its relay configuration: 2 retry queues + (max reservations + max circuits + 8) × (fixed part + 4 streams), where circuit sources need no reservation and the 8 cover dial races and reconnects whose old connection has not drained.

## The `unsafe` exception for Apple's fast datapath

The workspace forbids `unsafe`. One call is exempt: quinn-udp's `unsafe fn set_apple_fast_path`, made once per socket on every Apple target, iOS included, which switches quinn-udp to the private `sendmsg_x`/`recvmsg_x` (#359). It beat the regular path by 31% on the macOS bench. quinn-udp resolves both symbols through `dlsym` and falls back to `sendmsg`/`recvmsg` when either is missing, which is the guard the call relies on. `minip2p-quic` lowers `unsafe_code` from `forbid` to `deny` and scopes the call with one `#[expect(unsafe_code)]`; its `SAFETY` comment carries the justification, and `AGENTS.md` is unchanged. Apps distributed through the App Store accept the private-API review risk.

## Rejected alternatives

- **A shared write pool or a per-connection receive gate** to share the budget dynamically. ADR 0012 rejected both: a shared pool lets one connection starve the rest, and a receive gate stalls control frames other streams need.
- **Queueing admissions until memory frees up.** A dial or stream that waits for room hides the overload from the caller and holds state for work that may never run; refusing keeps every layer's view honest.
- **Reserving lazily as bytes arrive.** Admission would succeed and later fail mid-stream, which is the teardown ADR 0012 removed.
- **Sending a refusal before Retry.** It answers unvalidated, possibly spoofed sources.
- **Retry only under load**, as go-libp2p does with a token bucket of unverified attempts. Retry stays on for every inbound connection: it keeps spoofed Initials from claiming admission state, at one RTT per inbound handshake. A load trigger is cheap to build, but nothing has shown its benefit here; revisit it when handshake measurements or an application call for it (#361).

## Consequences

- A transport's queued QUIC memory is at most `memory_budget_bytes`, whatever the churn pattern; dual-stack no longer doubles any limit. One exception: datagrams from one receive call share an allocation (one GRO batch, or up to 32 datagrams where the platform batches receives without GRO, #371), and a stream chunk the engine still buffers keeps all of it alive while the engine counts only its packet. A peer padding its stream packets with junk datagrams can therefore pin up to that many times the reserved receive windows.
- With the default windows, a single connection buffers less in flight than the 10 MB windows it replaced. #361 then tuned them on an emulated 100 Mbit/s, 100 ms link: a 1,536 KiB stream window and a 1,216 KiB send window are the smallest that reach 90% of a large window's goodput, and the connection window grew to 5 MiB, though throughput alone needs 1.5 MiB, so three stalled streams still leave control streams credit. The default budget grew to 640 MiB to keep the 64-connection floor (65 with a stream each). Fat, short paths give some up: on 1 Gbit/s at 20 ms a single stream gets about half the link.
- A reader that never acknowledges now exhausts the budget, not just the connection slots: new streams and connections are refused until it acknowledges or abandons.
- TCP and circuits got their own memory budgets in the same terms: see ADR 0021 (#357).
