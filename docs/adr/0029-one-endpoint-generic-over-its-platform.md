# One `Endpoint<P>`, generic over its platform

The std `Endpoint` and `PortableEndpoint<T, E>` already ran one private engine, but each forwarded to it through its own copy of the API: about forty methods written twice, with diverging docs, and every new endpoint API (stream keys, a built-in write queue, protocol handles, `flush`) would be written twice too ([plan](../plans/dx-perf-size-evolution.md), Decision 2). The copies differed in only four things: where time comes from (std reads its clock, portable took a `now` argument on every call), which transport is driven and how it is bound, whether `/dns*` candidates are resolved, and whether there is a blocking wait. We decided:

- **One `Endpoint<P: Platform>` holds the engine and a platform `P`.** Every method that does not need an operating system is implemented once, on `impl<P: Platform> Endpoint<P>`: `connect`, `poll`, the stream operations, `ping`, pubsub, the state getters, `stats`, `shutdown_mdns`, and the rest. `P` defaults to `StdPlatform` under `std`, so `Endpoint` alone still names the std endpoint and `Endpoint::builder()` is unchanged. `PortableEndpoint<T, E, C>` is an alias for `Endpoint<Portable<T, E, C>>`.
- **`Platform` is sealed and supplies only what differs.** Its hidden half names the transport, entropy and mDNS carrier types and provides `now()`, the candidate expander (the std resolver, or concrete addresses only), and a non-blocking readiness harvest before each drive (the std readiness poll, a no-op on portable). Platform-specific surface stays in inherent impls on the concrete platform: binding, `wait`, `wait_handle`, `close_within`, `listen()`, and the WebTransport and relay-mesh controls on std; `listen_on` and `next_deadline` on portable. `close` is shared and dispatches through a sealed platform hook: `close_within(DEFAULT_CLOSE_TIMEOUT)` on std, two final drives at one clock sample on portable.
- **A portable endpoint samples a caller-supplied `Clock` instead of taking `now` per call.** Taking `now` everywhere is what forced the second copy: the same method could not have both signatures. The host already owns its time source (a hardware timer, `performance.now()`), so it hands that to the builder (`PortableEndpointBuilder::new(&identity, entropy, clock)`), and each call samples it once, exactly as the std endpoint samples its OS clock. Hosts that take one sample per turn themselves use `minip2p_core::platform::ManualClock` and `endpoint.at(now).poll()`, which sets it; deterministic tests do the same.
- **Close reports are one type.** The portable consuming `shutdown(now) -> ShutdownReport` becomes `close() -> CloseReport`, the std report type: two final drives (one runs the closes, one sends them), reported as std `close_within(Duration::ZERO)` reports (`Drained`, `DeadlineExpired` with connections left tracked, or `Failed`). The std mDNS-only `shutdown()` becomes `shutdown_mdns()`, which both platforms now have, so `shutdown` no longer means two things. `Drop` is generic too, so dropping a portable endpoint disconnects its peers, best effort, as a std one always did.
- **`std/mod.rs` is split as part of the move**: the platform and its inherent impl in `std/mod.rs`, the builder and binding in `std/builder.rs`, runtime-control errors in `std/errors.rs`, and its tests in `std/tests.rs`. The shared surface lives in `endpoint.rs`, the platform contract and `Portable` in `platform.rs`.

## Rejected alternatives

- **A caller-advanced clock stored by `poll(now)` with no other way to set time.** Calls between polls would then use a stale sample: a ping started long after the last poll would measure the gap into its RTT. `ManualClock` keeps that model available, but explicit.
- **Keeping `now` arguments on portable methods through an associated "time argument" type** (`()` on std). Every shared signature would carry a parameter that means nothing on std.
- **A public, implementable `Platform` trait.** Its internals are engine types; sealing keeps them private and leaves room to change the seam.

## Consequences

- Each endpoint API is written and documented once; `StreamWriter` loses its `write_at`/`close_write_at`/`observe_at` twins and works on any `Endpoint<P>` through `write`/`close_write`/`observe`.
- Portable builders take a clock, and the endpoint type gains a type parameter (`PortableEndpoint<T, E, C>`, `SmoltcpEndpoint<D, E, C>`). `Endpoint::portable(..)` is gone: an uninferable platform cannot hang a constructor on `Endpoint`, so `PortableEndpointBuilder::new` is the entry point, on `no_std` too.
- The engine stays monomorphized once per platform, as before: the WASM build's size is unchanged by the move.
