# Binary multiaddr decoding is as strict as the text parser

- The binary decoder (`Protocol` decoding in `minip2p-core`'s `protocol.rs`) runs the same `is_valid_dns` check on `/dns`, `/dns4` and `/dns6` bodies that the text parser applies. Without it, a peer-supplied binary address (Identify, beacons) could carry a name the text form cannot represent: a body containing `/` decodes to one component but prints as several, so re-parsing the text yields a different address, and one address would mean different things depending on which representation a check looked at. Control characters, whitespace and empty names are rejected for the same reason. The `wire_inputs` fuzzer found the original mismatch; tests assert parity in both directions.
- Declared lengths are compared as `u64` before any `usize` conversion, in `length_prefixed` (multiaddr values) and `decode_frame` (length-prefixed frames), so an absurd declared length (up to `u64::MAX`) is rejected identically on 32-bit and 64-bit targets instead of truncating on 32-bit.
- Only `/quic-v1` (0x01cd) is supported; the legacy `/quic` code (0x01cc) is deliberately rejected as an unknown protocol, in both text and binary forms.
