# TCP transport write path and poll ordering

How `TcpTransport` moves ciphertext and events, and in what order.

- **One flush point.** `TcpTransport::poll` retries every connection's buffered writes before it returns, whether or not the provider reported `TcpEvent::Writable`, so a provider that reports readiness coarsely, or not at all, still drains. `Writable` is therefore a no-op in `handle_provider_event`; a separate readiness path would be a second thing to get right.
- **`max_buffered_send = 0` holds one frame, not none.** `fill` always pulls at least one frame, or nothing would ever leave. Zero is the default because the provider's send buffer keeps the link busy while everything else waits in Yamux, which interleaves streams round-robin and sends control frames first.
- **Events are the host's even when a write fails.** `pump_and_flush` and `drive_connection` publish the session's events (and flush bytes it queued) before returning a failure.
- **Queued events first.** `poll` returns already-queued events before doing more work, so a host that acts between polls (opening a stream on a fresh `Connected`) acts against the state those events described. `next_deadline` reports `IMMEDIATE` while events are queued, which needs no retained clock sample, and while a linger is not yet stamped.
- **Error mapping on stream operations.** Yamux `Full` is backpressure (`TransportError::Full`), never a fault. Any other Yamux error (a closed write side, an unknown substream) is a `PollError` on a still-healthy session. Any other session error is fatal and tears the connection down; the one reachable from a stream operation is a local reset of a peer-opened stream exhausting the control reserve (`YamuxSession::reset`).
- **An empty write checks the connection first.** It is a no-op on a live connection but `ConnectionNotFound` on an unknown one, the same order the QUIC adapter applies.
- **A remote FIN ends the connection.** libp2p needs the byte stream in both directions, and Yamux carries its own orderly shutdown (`GoAway`) that would have surfaced first, so `TcpEvent::RemoteWriteClosed` closes the connection with an error.
- **Listening twice on a bound address is the same listener.** Hosts announce what they bound and then listen on it (the swarm's bind-then-listen does), so `listen` on an address the provider already reports returns it without binding again (which would fail with the address in use) and without announcing it again (which would grow the event queue for as long as a caller keeps asking).
- **Providers dial bare `/host/tcp/port` only.** `host_and_port`, shared by both providers, rejects any trailing component (`/p2p`, `/p2p-circuit`) with `TcpError::Address` instead of ignoring it, since dialing past it would connect somewhere the caller did not ask for. Names are refused too (ADR 0010: the `Endpoint` resolves `/dns*`), because a lookup inside `dial` would block the driver thread.
