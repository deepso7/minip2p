# TCP connection liveness: authentication deadline, send stall, keepalive

A `TcpTransport` connection can die three ways without the peer saying so, and each has its own timer, all folded into the connection's single wake-up (`Connection::wake_at`, ordered in `TcpTransport::timers`).

- **Authentication deadline (`handshake_timeout_ms`, default 30 s).** Generous next to the few round trips an upgrade takes, so only a peer that stopped participating trips it. It bounds the upgrade only: once the session is established `authenticate_by` is cleared, so a healthy connection is never torn down on a timer and an idle host is not woken for it.
- **Send stall (`send_stall_timeout_ms`, default 30 s).** `TcpTransport::poll` marks `stalled_since` before retrying a connection's buffered writes, keeping an older mark; `flush` clears it the moment the socket accepts a byte, and a fully drained buffer clears it too. Comparing buffer lengths across polls instead would miss progress the session refilled (a socket taking one frame per poll is not stalled), and leaving a stale mark after a drain would make the next socketful look like the tail of an old stall and fail the connection at once. While stalled, the connection sleeps until the stall becomes fatal instead of reporting an immediate deadline: spinning would not unstick the socket, and the provider's readiness wakes it sooner. Long enough that a briefly wedged peer recovers, short enough that a dead one does not hold a connection forever.
- **Keepalive.** Yamux keepalive is timed whether or not the outbound buffer has room: a backed-up write path to a dead peer is exactly what keepalive has to catch, so a ping that cannot get into the buffer is still timed. The session is polled after the write retry, so the poll dates a ping the retry just pulled, and a session whose last upgrade bytes just drained gets its first keepalive deadline in the same poll. A write the socket accepts after refusing proves the peer's TCP acknowledged data, so `flush` calls `note_peer_acked` and keepalive need not probe (#497). A socket that is merely accepting writes into free buffer space proves nothing: the deadline stands.
- **Wake-up shape.** A connection with framed bytes and room for them, or a socket still taking bytes, reports an immediate wake-up; one waiting only on a timer reports the timer; the `work` set keeps only connections with a backlog after their poll, or every serviced connection would be serviced forever.
