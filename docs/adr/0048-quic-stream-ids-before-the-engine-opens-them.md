# QUIC stream IDs are handed out before the engine opens them

`QuicConnection::open_stream` returns a stream ID at once, even when the local active cap is full or the peer has granted no stream credit yet. Opens wait FIFO until both local capacity and peer credit allow binding in the engine (reported as `StreamOpened`); non-empty writes return `Full` until then, without consuming shared send capacity needed by bound streams to finish. An armed writer receives `StreamWritable` after binding when send room allows. FIN may queue while waiting. Only bound streams count against `max_streams_per_connection`, including closed streams with unacknowledged bytes. The pending-open queue has no length cap: only local callers enqueue requests, so a remote peer cannot use it for DoS.

- The adapter is the only opener of local streams, so IDs follow its own sequence (`next_local_bidi_stream_id`, step 4). An engine ID that differs from the expected one fails the connection.
- Resetting a stream that is not on the wire yet completes it for the caller immediately and marks it `reset_on_bind`: it is still opened in the engine when credit arrives, then reset, so the ID sequence never diverges. Closing the connection ends every send half, bound or not; an unbound stream then never opens.
- A closing connection opens nothing more. On a WebTransport session a pending open may also wait on the client's session stream credit.
- Binding retries after local stream GC releases capacity and when quinn-proto reports `StreamEvent::Available` for bidirectional peer credit. A reset tombstone consumes its engine ID without taking a bound application slot or emitting `StreamOpened`.
