# TransportSet routing and failure isolation

`TransportSet` (`minip2p-transport`) combines one member per address shape (`TransportKind`). We decided how it routes work and how it keeps one member's faults from costing another its events:

- **Connections route by namespace, addresses by shape.** Every call about an existing connection goes to the member that claimed the id's `ConnectionNamespace` (`index_for_id`); no address is consulted, so routing is a lookup rather than a search. A member may claim several namespaces (the dual-stack QUIC transport allocates in `QUIC_IPV4` and `QUIC_IPV6` and keeps that split to itself), but a namespace has one owner (`DuplicateNamespace`), because an ambiguous id would deliver a connection's work to the wrong transport. A member that claims no namespace is refused (`NoNamespace`): nothing it returned could be routed back to it. Dials and listens go to the member serving the address's `TransportKind`; an address with no transport kind (a relay `/p2p-circuit` address) is refused rather than guessed at, since it is someone else's to dial.
- **Unknown ids.** An id in a namespace nobody claims is `ConnectionNotFound`, the same as a connection that does not exist; `ack_stream` and `set_control_stream` on one are no-ops, as for any unknown connection.
- **Mis-claimed dials fail.** If a member's `dial` returns an id outside the namespaces it claimed, the set closes that connection (best effort; the close error cannot be retried or reported through the set's API, so it is dropped) and returns `DialFailed`. Handing the id back would give the host a connection every later call reports as not found while the member still pays for it.
- **Refused transports are handed back.** `insert` returns a rejected transport in `RejectedTransport` instead of dropping it: by the time it is offered it owns a bound socket, and dropping it would close a listener the host believes it has.
- **Datagrams route like dials.** `send_datagram` goes to the member that would dial the target, because a hole punch has to leave from the socket its connection will arrive on; a sibling would open a NAT binding for packets that never come. A transport with no datagram of its own (a stream transport) answers `TransportError::Unsupported`, not a failure, so a caller choosing between transports can tell "not here" from "this failed".
- **A failing member does not bury its siblings.** `poll` polls every member even after one fails, keeps the events collected so far in `pending`, and returns the first failure; the next `poll` delivers the held events before polling anyone again, then any remaining failures. That bounds the queue to one round and means a member that fails every time cannot hold a healthy sibling's events forever: the host alternates between hearing the fault and draining what still works. While events or failures are held, `next_deadline` is `Deadline::IMMEDIATE`; otherwise it is the earliest member deadline.
- **Addresses come from every member.** `local_addresses` and `active_inbound_connection_sources` concatenate every member's answer, each asked its own question: where we are bound is not where peers reached us, and leaving out a member would hide a way to reach the host.
- **The circuit bit stays readable.** `ConnectionNamespace::CIRCUIT` is `0x80` so circuit ids have the top bit of their `u64` set, and every built-in non-circuit namespace keeps it clear, because hosts and wire logs may read that bit directly. `is_circuit` still compares the namespace tag, not the bit, since custom namespaces above `0x80` also set it.
