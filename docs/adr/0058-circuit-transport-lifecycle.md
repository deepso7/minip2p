# Circuit transport lifecycle: ids, teardown and error mapping

Decisions in `minip2p-circuit`'s `CircuitTransport` that a reader could otherwise "simplify" away:

- **Ids are consumed only after every fallible step.** `adopt_bridge` peeks the next circuit id up front but calls `circuit_id_allocator.allocate()` only once entropy and validation have succeeded, so a failed adoption leaves the id space untouched. A peek/allocate reordering would silently burn a sequence number per failed adoption; the id-space assertion in the circuit tests is the only guard.
- **Pending bridge data is already acknowledged.** `BridgeAdoption::pending_data` (bytes read past the relay's CONNECT/STOP response) was acknowledged on the bridge by whoever read it, so `adopt_bridge` feeds it to the session without acknowledging again; `inject_bridge_data` acknowledges because the circuit itself consumed those bytes.
- **Feed, then pump either way.** `feed_bridge` pumps the session even when `handle_input` failed: bytes the session queued and events it produced before failing belong to the caller regardless.
- **Retired bridges are remembered, but boundedly.** After a circuit's public `Closed`, its bridge key stays in `retired_bridges` so late inner-transport events for it are suppressed, and late `StreamData` is acknowledged (discarding it consumes it). The set is capped at `MAX_RETIRED_BRIDGES` (1024) because a peer may never finish closing its half of a gracefully closed bridge.
- **Cleanup is best effort and never changes the outcome.** When a circuit fails (`fail_circuit`), is closed, or the wrapped transport collides with the circuit id namespace (`dial`, `reject_inner_collision`), errors from resetting the bridge or closing the inner connection are ignored: the circuit is already retired, so exactly one `Closed` (or the namespace-violation `Error`/`DialFailed`) is reported whatever the cleanup returns.
- **Close is graceful only for an established session.** `close` sends a Yamux GoAway and flushes; a circuit still negotiating has no Yamux session, so `go_away` refuses and the bridge is reset instead (also when the flush or the bridge FIN fails). A remote GoAway tears substreams down exactly like a local close: a `StreamClosed` per substream, then `Closed`, so both ends of a graceful shutdown see the same sequence.
- **One report per failure.** A failure discovered while flushing during `send_stream` (the relay connection died between polls) ends the circuit and is returned as `ConnectionClosed`, followed by one `Closed` carrying the reason, never an extra `Error`, so the swarm does not report it twice. `set_control_stream` has no return value, so a flush failure there tears the circuit down with the failure as its close reason.
- **Session error mapping.** Yamux `Full` maps to the retryable `TransportError::Full` (ADR 0012); other Yamux refusals (closed write side, unknown substream) to a non-fatal `PollError`, because the session is still healthy. Local opens beyond `max_streams` wait FIFO instead of failing with `TooManyStreams` (ADR 0038), and `StreamOpened` surfaces only when the SYN is pulled for writing. Any other `SessionError` is fatal (for example a local reset of a peer-opened stream exhausting the control reserve, see `YamuxSession::reset`) and fails the circuit.
- **Stream ids are not truncated.** Circuit substreams are Yamux `u32` ids carried in a `u64` `StreamId`; an id congruent to a live substream modulo 2^32 is rejected, never truncated onto it.
- **Pending events need no clock.** `next_deadline` returns `Deadline::IMMEDIATE` whenever events are buffered, because they are due whatever the host clock reads, so no time sample is retained.
