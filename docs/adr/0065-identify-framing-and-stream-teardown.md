# Identify framing, validation order and stream teardown

`IdentifyProtocol` (`minip2p-identify`) follows the libp2p identify spec on the wire and tears its streams down so that no swarm or transport state outlives an exchange:

- **Length-prefixed frames.** Each identify message goes out as a varint length prefix followed by the protobuf body (`encode_frame`), as the [identify spec](https://github.com/libp2p/specs/blob/master/identify/README.md) requires. Without the prefix, rust-libp2p and other peers read the first body bytes as a length varint, which usually lands on wire type 4 and is rejected as a "deprecated group".
- **Binary multiaddrs.** `observedAddr` and `listenAddrs` carry the multicodec binary encoding (`Multiaddr::to_bytes`), the shape foreign peers expect, never the string form.
- **No wildcard hosts.** `register_outbound_stream` leaves out listen addresses with a wildcard host (`0.0.0.0`, `::`): that is a bind address, not one a peer can dial.
- **Validate before registering.** `register_outbound_stream` encodes and size-checks the message before it records the stream, so a refused message (`IdentifyError::MessageTooLarge`) leaves no registration behind and a later identify on the same peer is not rejected as `StreamAlreadyRegistered`.
- **Receive budget.** `register_inbound_stream` sizes a stream's `FrameExchange` for `MAX_MESSAGE_PARTS` frames at their maximum: the first frame is the exchange's own frame, the rest ride behind it as trailing bytes (go-libp2p sends its signed peer record as a second frame). Bytes that overflow that budget are refused before they are buffered, since nothing legal can still be growing towards one message.
- **Reset on refusal, not half-close.** When `on_stream_data` refuses bytes it drops the stream's state and queues `ResetStream`. A half-close would wait for the remote's own half-close, which then finds nothing to act on, and a remote that never sends one would keep the stream and its swarm and transport state allocated for the life of the connection.
- **The initiator closes its write side.** `on_stream_remote_write_closed` queues `CloseStreamWrite` even though the initiator sends no identify data: multistream-select wrote on the stream, so the transport still considers the local write side open, and without this FIN the stream never reaches `Closed` and the swarm's stream-owner entry and the transport's per-stream state leak for the life of the connection.
