# mDNS driver: congestion is parked, impossible sends are dropped, stale packets are discarded

`MdnsDriver` (crate `minip2p-mdns`) treats the outcomes of `MdnsIo::send` differently, because a carrier that only moves bytes when it is driven (the in-process smoltcp stack) fills its send ring inside a single tick, exactly when a burst of announcements is queued. We decided:

- **`MdnsError::Congested` is backpressure, not a fault.** `send_batch` parks the datagram that did not fit in `pending_action` and stops the batch; nothing is queued behind it, since whatever would go next waits on the same drain. The next `turn` sends the parked datagram first, before anything new, after the carrier has been polled. A burst is delayed, never lost, and mDNS does not fail because a device spoke faster than its link could carry. The hosted socket carrier maps `io::ErrorKind::WouldBlock` to `Congested` (`socket::send_error`) for the same reason: the driver backs off on any `MdnsError::Io`, so treating kernel send-buffer pressure as a failure would take the host off the link at every busy moment.
- **`UnknownInterface` and `Oversized` are dropped, not parked.** An interface that left between encode and send takes its packet with it; a datagram larger than the carrier's whole send buffer can never be sent, and parking it would retry an impossible send every turn forever (and keep `next_deadline` at "now" for good). `SmoltcpMdnsIo::send` therefore checks the payload against `payload_send_capacity` / `packet_send_capacity` before attempting it, because smoltcp refuses an oversized datagram with the same `BufferFull` it uses for a momentarily full ring. The documented cost of shrinking the smoltcp buffers below a claim's size is a dropped claim, not a stuck driver.
- **A hard I/O failure keeps the datagram parked** for the retry, like congestion, and the driver backs off for `MDNS_FAILURE_RETRY`. A refresh that fails stays due, so the retry repeats it. A repeat of the same failure (same operation and interface, see `same_failure`) is not re-reported; a different one is.
- **A parked or scheduled packet never outlives the snapshot it was encoded from.** Encoded responses embed the expansion of wildcard listen addresses against the interface addresses, so a change to either makes them stale even when a stable `InterfaceId` survives. `MdnsAgent::set_interfaces` clears every scheduled response and pending action on any snapshot change (and restarts the fast probing phase; the same interfaces again are not a change), and the driver drops `pending_action` when `io.refresh()` reports a change or `set_local_addrs` reports a change. Otherwise the parked packet, sent first on the next turn, would announce an address the host no longer has.
- **The smoltcp carrier drains its own ring before reporting congestion.** On `udp::SendError::BufferFull`, `SmoltcpMdnsIo::send` drives the stack once and retries, so a datagram goes out now instead of being parked for a whole turn; only if the link still is not taking frames does it return `Congested`.
- **The smoltcp carrier's interface set is what the interface holds now.** `send` resolves the target against the current snapshots, not against the sockets that outlive an address: a family whose last address went away answers `UnknownInterface`, so the driver drops the packet instead of handing smoltcp one it has no source address for.
