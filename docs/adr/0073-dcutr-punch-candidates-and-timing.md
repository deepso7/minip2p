# DCUtR punch candidates and timing

How `minip2p-nat` chooses the addresses it punches and when it punches:

- **Candidates come from trusted observations.** Identify's `observed_addr` is the remote's view of our transport address; behind a NAT it is our public mapping, the only usable punch candidate since bound addresses are private. It is recorded only from configured relays and AutoNAT servers: believing any connected peer would let it aim punch-time UDP blasts at an address of its choosing. The Identify event stays visible to the application.
- **A reporter vouches only for its own connection's IP family.** It sees us only over that family, so a dual-stack host learns its IPv4 mapping from one reporter and its IPv6 mapping from another. A relayed connection has no IP of its own (the reporter sees the relay), so it vouches for no family, and a reporter's claim in another family does not evict its claim in its own.
- **Only concrete IPs are punched.** A DNS name must not take an IP family's quota, and the receiver drops it anyway. An IPv4-mapped IPv6 address is judged as the IPv4 address it carries.
- **Only global unicast addresses qualify** (`is_global_unicast_v4`/`_v6`). Excluded IPv4: RFC 1918 private space, RFC 6598 carrier-grade NAT space, loopback, link-local, IETF protocol assignments 192.0.0.0/24 (except the globally reachable anycast .9 and .10), the documentation ranges, benchmarking 198.18.0.0/15, and multicast/reserved/broadcast. IPv6 must be in 2000::/3; special-purpose allocations in 2001::/23 are excluded except the few IANA designates globally reachable, as are 6to4 (2002::/16) and the documentation ranges (2001:db8::/32, 3fff::/20).
- **RTT is measured from when CONNECT was actually written.** If the CONNECT write is held (refused as Full), the clock starts when the host reports it written (`on_write_completed`), not when it was queued; each round measures its own RTT. The first blast is due half the RTT (rounded up) after the reply; at zero RTT it leaves in the same cascade as SYNC, so the mapping is open before SYNC can reach the remote and make it dial. The punch window starts after the first blast, so a long RTT cannot expire the window before it.
- **The source punches once it reads SYNC.** Sending SYNC arms `expect_punches` for the source until the budget deadline.
- **For QUIC the DCUtR responder only blasts; the initiator dials.** A responder dial would race the initiator's, and when both land the second connection replaces the first and ends its streams.
