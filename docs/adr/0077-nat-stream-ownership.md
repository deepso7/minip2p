# NatAgent stream ownership: reset, release, and hand-off

`NatAgent` claims every stream a NAT machine uses in its registry (`Shared::own_stream`, `owned_role`) and decides per case whether a stream it gives up is reset, merely released, or handed to someone else:

- **A stopped control stream is reset.** Every NAT control stream (HOP, STOP, DCUtR, AutoNAT) must write, so `StreamStopped` on an owned stream resets it; its `StreamClosed` then retires the owning machine.
- **A stream on a terminal connection is released without a reset.** When the owning connection has closed or been replaced (`Attempt` relay leg, the reservation manager in `housekeeping`, `InboundCircuit`), local state is dropped with `release_stream`; there is nothing left to reset, and the agent drops a dead connection's registry entries itself.
- **A finished exchange releases its stream at once**, so a write tail and FIN the swarm still holds for it are replayed without registry ownership. `NatAgent::handle` still routes such held streams (`swarm.held.is_held`) so the tail goes out in order before the close.
- **A bridged HOP/STOP stream belongs to the circuit transport from promotion on.** Only unbridged HOP streams still route to an attempt, and cancelling an attempt resets only those; a bridged stream is never reset by NAT.
- **A refused STOP stays NAT's until it closes.** After `InboundCircuit` answers a STOP CONNECT with a refusal and closes its write side, the stream stays registered so late relay bytes are consumed by NAT and never surface as an application stream. A bridge the swarm refuses to promote is closed for the same reason.
- **Only STOP is served, and only from configured relays.** All four NAT protocol ids (HOP, STOP, DCUtR, AutoNAT) are registered so the client-side machines can negotiate outbound streams and advertise support through Identify, but an inbound stream for any other NAT protocol, or a STOP from an untrusted peer, is reset and kept owned; otherwise it would leak to the application as an ordinary stream despite its id being reserved.
- **A remote half-close is protocol input, not teardown.** `RemoteWriteClosed` on a HOP or STOP stream is fed to the sans-I/O machine (`on_remote_write_closed`), which may still hold a complete frame and may still write; the circuit is kept until its normal exchange deadline. A promoted bridge starts with `remote_write_closed: false` because CONNECT completion promotes in the same input cascade, so no half-close can arrive while NAT owns it.
- **Reaping is driven by touched state.** `NatAgent::handle` calls `reap_done` only when an event actually visited a NAT machine; foreign application stream events stop after one registry lookup.
