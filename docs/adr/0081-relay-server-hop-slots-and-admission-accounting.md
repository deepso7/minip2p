# Relay server: HOP worker slots, token spending and IP accounting

Admission rules in `RelayServerAgent` (crate `minip2p-relay-server`) that a reader would be tempted to "simplify", each closing a resource-exhaustion hole or keeping limits honest (see ADR 0018 for the per-key limits themselves):

- **Every HOP worker on a connection holds a HOP slot, not only those still waiting on a reply.** A finished worker stays to claim its stream's events until the peer closes the stream; counting only waiting workers would let a peer that never closes its streams open one HOP stream per muxer slot, on every connection it holds. Circuit legs (committed or pending) keep their worker too but are excluded from the HOP count, because `max_circuits` and `max_circuits_per_peer` bound them instead. A CONNECT whose circuit never commits (the destination refuses) is back in the count. `on_hop_ready` counts only this connection's workers, via a key range.
- **A request costs a rate token only once admitted.** `decide_connect` consumes the circuit token only after every limit check passes and a route is found (a mesh entry node that resolves no claim spends nothing, so a later entry node can still get the source through). Reservation renewals on the same connection keep the admitted reservation alive, keep the IP key it was admitted under, and spend no token.
- **A stale reservation still counts its IP, but is no destination.** `decide_connect` looks up the reservation and its connection once: the connection's IP counts toward the per-IP circuit cap even when the reservation is no longer live, while only a live one (`live_reservation`) is a STOP target. Only a local STOP carries the destination's IP into the pending circuit; a stale local reservation's IP must not ride along to a mesh forward. If the destination reserves locally after admission, `resolve_waiting` adds its IP to the circuit's accounting, under the same `max_circuits_per_ip` cap.
- **The STOP open is checked against the reservation's connection.** The swarm may be ahead of the events the agent has seen, and `open_stream` is peer-scoped: a stream that lands on a connection that replaced the reservation's is retired and the CONNECT answered `NO_RESERVATION`. ADR 0028 applies the same rule to backbone opens.

IPv4-mapped IPv6 addresses are keyed as their IPv4 address (ADR 0018, amendments).
