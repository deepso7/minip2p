# Building and binding the std Endpoint

`EndpointBuilder::bind` (std) validates the whole configuration, then binds every transport's sockets before returning the `Endpoint`. Decisions it encodes:

- **Validation happens at bind, before any socket.** Setters may run in any order (announce addresses before the WebTransport certificate option, say), so cross-option checks such as `check_webtransport_announce` run in `bind` once every option is in, and runtime setters (`set_relay_server_announce_addrs`) run the same check and keep the old value when they refuse. Every configuration error (reserved protocol ids, zero timeouts, discovery and mDNS configs, the TCP namespace) is reported before a socket is allocated, so an unbindable address never masks it.
- **An endpoint with no transport is refused.** It could neither dial nor be reached; failing at bind says so once, where the mistake is, instead of at every later call.
- **Sockets are bound at build time, and listening arms every transport.** QUIC and TCP both bind their listen addresses in `bind`, so a caller that asked for port 0 learns its port from `listen_all` before driving anything. `listen`/`listen_all` then arm every bound transport, not just the first, and report an address for each: a transport left out would be unreachable, or invisible to peers, with no way for the host to tell.
- **A transport claims an address shape, not a family.** QUIC has one socket per family: `quic-v1` and WebTransport listen addresses are grouped onto it, and another port or the same shape twice is refused. TCP binds one socket per `/tcp` address on one transport, rather than a second TCP member, which the transport set would refuse.
- **The address decides the transport; the connection namespace names it.** Nothing above the endpoint chooses a carrier: the transport set routes a dial by address shape, and the namespace on the returned `ConnectionId` is how a connection id is routed back to the transport that minted it. So `bind_tcp_member` refuses a `TcpConfig::namespace` other than `TCP_IPV4`/`TCP_IPV6` before binding: tagged as another carrier's, TCP's ids would name the wrong transport and take a claim a QUIC member needs.
- **The discovery topic is validated by the std setters.** The beacon setters check the topic, so pubsub refusing it during setup is a bug (`BindError::Invariant`); the portable builder takes its config unchecked and reports the same failure as `PortableBuildError::Topic`.
- **`Endpoint` is `Send`, asserted at compile time,** because ffi-core's detached driver moves the endpoint onto its own thread.
