# Relay bridge promotion in the Endpoint's NAT host

The Endpoint's NAT host (`NatDriver` in `crates/minip2p/src/nat.rs`) turns a relay bridge stream into a circuit connection by handing it to the circuit transport (`CircuitOps::adopt_bridge`) and keeps a `promoted` map from `(inner relay connection, bridge stream)` to the circuit's `ConnId`. The relay stack is the same above the dial whatever carries it: HOP and STOP are ordinary streams on an established relay connection and the circuit rides that connection, so a TCP relay (the only option on a device without an operating system) carries circuits exactly like a QUIC one. We decided:

- **Owed bytes go first, in order.** At promotion, bytes the swarm refused as Full are still owed to the peer: the swarm core's (a negotiation reply) from `SwarmCore::forget_stream`, then the agent's held tail (a STOP STATUS) from the handoff's `unsent_data`. They become the adoption's `unsent_prefix` in that order, because from adoption on the circuit, not the swarm, takes the bridge's `Writable`.
- **The agent acknowledges what it reads; the circuit acknowledges only what it reads itself.** `ingest` acks every `StreamData` the agent handled, including bytes past a CONNECT response that the promoted circuit takes as adoption data (`pending_data`).
- **Stragglers are routed, not re-handled.** Swarm events for a promoted bridge (data, remote FIN, write stop, close) are injected into the circuit transport; the swarm's copy of `StreamWritable` is dropped, since the circuit sees the bridge's writability straight from the transport.
- **A circuit is only as alive as the connection carrying it.** When the carrier relay connection closes or is replaced (a replacement ends its streams), every bridge it carried is closed through `inject_bridge_closed` and its promotions are dropped, so neither side keeps a connection to a peer it can no longer reach. A circuit that vanishes without a lifecycle event the driver saw (for example a remote reset of the bridge before the circuit established, which surfaces as a transport error naming the circuit rather than as `ConnectionClosed`) is forgotten by the bounded sweep in `tick`, once per batch.
- **A failed `CloseCircuit` keeps the promotion.** Only `Ok` or `ConnectionNotFound` drops it; any other transport failure will surface through the normal event path, which then cleans up.
- **A bridge the circuit did not adopt is reset.** Except for `AdoptError::UnknownConnection`, a failed adoption resets the bridge stream on the wrapped relay connection, because it is dead to both sides.
- **No circuit operations is an error, not a panic.** The Endpoint refuses relay configuration over a transport without circuit operations, so `promote` without `CircuitOps` is reached only for a relay the agent was never given; it fails with `PromoteError::Failed`.
