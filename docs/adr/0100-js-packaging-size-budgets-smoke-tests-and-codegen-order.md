# JS packaging: size budgets, a real browser-SDK smoke test, and React Native codegen order

- **The browser SDK's wasm has a size budget.** `verify-release-packages.mjs` caps the packaged `@minip2p/web` wasm at 4 MiB (`maximumWasmBytes`), because every page using the browser SDK downloads it. The cap is raised only deliberately; it went to 4 MiB with relay reservations and circuits (3.65 MB, 0.57 MB gzipped).
- **The browser package is smoke-tested without a browser.** `smoke-release-install.mjs` exercises `@minip2p/web` in Node: its `./manual` entry, given the packaged `.wasm`, builds a real endpoint.
- **Native size checks report everything before failing.** `react-native/scripts/check-native-size.mjs` reports every native artifact's size change before failing, so one regression does not hide the rest.
- **React Native generated code: customize before codegen, normalize after.** `react-native/scripts/normalize-generated.mjs` post-processes ubrn's generated TurboModule in two steps. `customizeGenerated` adds the mDNS hooks and must run before React Native codegen reads the spec, since codegen reads the customized spec. `normalizeGenerated` trims whitespace and must run after every generator. `generate-codegen.mjs` runs them around codegen (customize, codegen, normalize); running `normalize-generated.mjs` directly (as the `build` script does) runs both back to back.
