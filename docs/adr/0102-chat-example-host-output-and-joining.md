# Chat example: what the host prints and how a joiner waits

`examples/chat` (`minip2p-chat`) is both a demo and the pubsub E2E test (`examples/chat/tests/chat.rs`), so a few behaviours are load-bearing:

- **Two address forms.** The host's `bound=` line is same-host pasteable: wildcard binds are rewritten to loopback, which the E2E test relies on. The raw `listen-addr=` lines carry the real binds; a remote joiner substitutes the host's public address for a wildcard host.
- **The circuit address is reprinted on every reservation.** A reservation that lands after the startup wait already warned, or is re-acquired after a loss, still prints its `circuit=` line; joiners have nothing to paste otherwise.
- **Joiners listen and subscribe before the path is ready.** The host announces its topic once per connection, and that can land while the joiner is still waiting for a path or Identify, so the joiner subscribes first. Listening seeds the NAT agent's bound addresses (the local half of the DCUtR candidate set). A circuit target's relay leads the relay list and `--relay` adds a fallback. Without relays, discovery's own NAT agent dials the mesh directly. A failed first Identify closes the connection, so the joiner treats it as fatal.
- **The chat loop drains stdin in bounded batches.** A pipe can produce lines far faster than a human, so the per-tick drain is capped to keep the network pump (`wait`) live under a stdin flood. Signalling EOF to the receiver is best effort: it may have exited after an endpoint error, which is already the primary outcome.
- **Pubsub routing in the E2E test** depends on subscription exchange performing low-watermark mesh admission, so directly connected peers are routable without sleeping a heartbeat; the hub eagerly admits both leaves before its first heartbeat, and a message relayed through the host arrives exactly once (seen-cache dedup), with the sender seeing only its local echo. The test helper merges each child's stderr into its output so a crashing child surfaces its real error.
