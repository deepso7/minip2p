# Relay server binary: advertised addresses and service install

`examples/relay-server` (`minip2p-relay`) is the deployable relay, and its startup and `service install` paths encode these decisions:

- **Advertised addresses.** Wildcard listeners are never advertised; with nothing announced the relay still grants reservations, with an empty address list. A CA-signed WebTransport certificate names a domain, so browsers dial the announced `/dns` address (a listener's IP fails the certificate's name); a derived certificate is dialed only by `/certhash`, which the relay logs as `webtransport=`, so the addresses `config` derives from `hostname` include a `/dns/.../webtransport` address only for a CA certificate. The mesh address it prints is what other nodes list in `[mesh] members` (or `--mesh-member`), with a wildcard IP replaced by this node's public one. The backbone transport binds one socket per address family, and one socket serves both the relay and the backbone where configured.
- **Certificate reload.** The certificate files are watched before the first load, so a renewal in between is noticed; certbot's deploy-hook order (chain first, then key) must be tolerated.
- **Validation happens before anything irreversible.** `service install` builds the Endpoint configuration first, and checks addresses the Endpoint would also check (the builder binds nothing), so a bad config fails before sudo matters and before it replaces a working config. An ephemeral public identity cannot be shared with the other mesh nodes, so mesh mode requires a persistent key.
- **Service identity.** The systemd unit always passes one fixed key file, so the peer ID survives restarts; it must be that exact path spelling, because `Path` equality ignores a trailing slash and `open` does not, and any other path would bypass `--import-key`'s refusal to replace the service identity (the CLI default is an ephemeral key). The unit runs from an unspecified directory, so every path it uses is absolute.
- **Atomic writes.** `write_atomically` re-applies the file mode after `open`, because the umask may have narrowed it. On failure the temporary file is removed best effort, and the primary write or install error is returned rather than the cleanup error.
- **Operator input is bounded.** Piped stdin is read through a bounded channel, so a producer cannot outrun the operator loop and grow the process without limit.
- **Allocator.** musl release builds use mimalloc (recorded in `examples/relay-server/Cargo.toml`).
