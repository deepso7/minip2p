# Relay server event benchmarks measure the agent alone, at three population sizes

`crates/relay-server/benches/relay_server_event_ir.rs` counts instructions for single agent operations (via `library_benchmark`). We decided:

- **Every scenario runs at N = 100, 1k and 10k** active reservations and circuits. Reserved peers `r0..rN-1` each hold one connection; `N / 100` source peers each hold one connection carrying 100 circuits to 100 distinct reserved peers. The first `EXPIRING` reservations are committed at `EARLY`, the rest at `NOW`, so one tick at `EXPIRY` expires exactly that batch. Every limit has headroom above N, circuits outlive the reservation expiry, and rate limits stay on (admission walks N+ live buckets) without any bucket refilling inside the measured window, so the only due work is the operation under test. A count that stays flat across sizes shows the operation does not scan the population.
- **The measured region is the agent alone.** A real swarm updates its own state before delivering an event, so each setup applies the event to `BenchSwarm` first and the fake's bookkeeping stays out of the count. The agent issues its swarm commands inline on `BenchSwarm`, so the measured region includes issuing writes, acknowledgements and resets. Each benchmark returns its inputs so their drop and the `teardown` assertions stay outside the measured region.
