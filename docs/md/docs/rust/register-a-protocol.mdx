---
title: Register a protocol
description: Register an application protocol, negotiate streams, exchange bytes, and close or abandon stream state on purpose.
---

Application protocols use libp2p multistream-select negotiation over an authenticated connection. Both peers must register the same versioned protocol ID. `connect` first; open streams once the peer is connected. Waiting for [`PeerReady`](/docs/rust/concepts#connection-readiness) is optional when you want Identify's advertised protocols before opening.

```rust
const ECHO_PROTOCOL: &str = "/my-app/echo/1.0.0";

let mut node = minip2p::Endpoint::builder()
    .protocol(ECHO_PROTOCOL)
    .listen_default()?
    .bind()?;
```

You can also call `add_protocol` after binding. Registration affects inbound and outbound negotiation.

<Callout type="warning">

`/ipfs/id/1.0.0` and `/ipfs/ping/1.0.0` are owned by the endpoint. Registering an ID in `RESERVED_PROTOCOL_IDS` on the builder fails `bind` with `minip2p::BindError::Swarm(minip2p::SwarmError::ReservedProtocol { .. })`; `add_protocol` rejects it with `minip2p::Error::Swarm(minip2p::SwarmError::ReservedProtocol { .. })`.

</Callout>

## Open an outbound stream

Once the attempt settles `Connected`, request a stream. A protocol both peers registered does not need to wait for Identify; match `PeerReady` first only if you want unsupported protocols to fail early with `RemoteDoesNotSupport`.

`open_stream` starts negotiation and returns a `StreamKey`: the connection and the allocated stream ID, together, since stream IDs are unique only per connection. Every stream operation takes it and every stream event carries it as `stream`. Wait for the matching `EndpointEvent::StreamReady` before writing:

```rust
use std::time::{Duration, Instant};

use minip2p::{ConnectOutcome, EndpointEvent, EndpointWaitOutcome};

let peer_id = target.peer_id().clone();
let connect_id = node.connect(target)?;
let mut stream = None;
let deadline = Instant::now() + Duration::from_secs(10);

loop {
    let event = match node.wait(deadline)? {
        EndpointWaitOutcome::Event(event) => event,
        // Another thread woke the wait; nothing to service here.
        EndpointWaitOutcome::Deadline => return Err("stream exchange timed out".into()),
        _ => continue, // interrupted by a WaitHandle
    };

    match event {
        EndpointEvent::ConnectSettled {
            connect_id: id,
            outcome,
            ..
        } if id == connect_id => match outcome {
            ConnectOutcome::Connected { .. } => {
                stream = Some(node.open_stream(&peer_id, ECHO_PROTOCOL)?);
            }
            other => return Err(format!("connect failed: {other:?}").into()),
        },
        EndpointEvent::StreamReady {
            peer_id: peer,
            stream: ready,
            protocol_id,
            ..
        } if peer == peer_id && Some(ready) == stream && protocol_id == ECHO_PROTOCOL => {
            // The endpoint queues what the stream cannot take yet (see Write
            // backpressure below), and the FIN waits behind it.
            node.send_stream(ready, b"hello".to_vec())?;
            node.close_stream_write(ready)?;
        }
        // The peer half-closed after its reply (delivered as StreamData):
        // the exchange is done, and our FIN went out before it was echoed.
        EndpointEvent::StreamRemoteWriteClosed { stream: done, .. } if Some(done) == stream => break,
        other => handle_other_event(other),
    }
}
```

Put this match in the application's ordinary event dispatcher. Do not discard events for other peers or streams while waiting for negotiation.

QUIC is a byte stream: writes can be fragmented or coalesced. Add framing when one application message must be distinguishable from the next.

## Accept an inbound stream

Inbound negotiation produces the same `StreamReady` event with `initiated_locally: false`. Track accepted streams by their `StreamKey` so later `StreamData` can be routed to the correct handler:

```rust
use std::collections::HashSet;

use minip2p::{EndpointEvent, StreamKey};

let mut echo_streams: HashSet<StreamKey> = HashSet::new();

match event {
    EndpointEvent::StreamReady {
        stream,
        protocol_id,
        initiated_locally: false,
        ..
    } if protocol_id == ECHO_PROTOCOL => {
        echo_streams.insert(stream);
    }
    EndpointEvent::StreamData { stream, data, .. } if echo_streams.contains(&stream) => {
        // Every chunk is echoed in order: the endpoint queues what a full
        // stream cannot take yet. A failure ends this stream, not the listener.
        if let Err(error) = node.send_stream(stream, data) {
            eprintln!("echo on stream {stream} failed: {error}");
            echo_streams.remove(&stream);
            let _ = node.reset_stream(stream);
        }
    }
    EndpointEvent::StreamRemoteWriteClosed { stream, .. } if echo_streams.remove(&stream) => {
        // Mirror the FIN, behind every echoed byte still queued.
        node.close_stream_write(stream)?;
    }
    _ => {}
}
```

## Dispatch by protocol handle

Each registered protocol has a `ProtocolId`, a `Copy` handle numbered by the endpoint. Look it up once and compare it with `StreamReady`'s `protocol` instead of comparing strings; `open_stream` takes the handle too:

```rust
use minip2p::EndpointEvent;

let echo = node.protocol_id(ECHO_PROTOCOL).expect("registered on the builder");
// `add_protocol` returns the handle of what it registers.
let chat = node.add_protocol("/my-app/chat/1.0.0")?;

match event {
    EndpointEvent::StreamReady { stream, protocol, .. } if protocol == echo => {
        echo_streams.insert(stream);
    }
    EndpointEvent::StreamReady { stream, protocol, .. } if protocol == chat => {
        start_chat(stream);
    }
    _ => {}
}
let stream = node.open_stream(&peer_id, chat)?;
```

A handle belongs to the endpoint that issued it: peers number their protocols independently, and `protocol_name(id)` gives the string back. `StreamReady` keeps the string `protocol_id` as well.

## Write backpressure

A stream accepts only as much as it can queue, so a slow reader slows the writer instead of tearing the connection down. `send_stream(stream, data)` takes anything that converts into `Bytes` and handles the rest for you: what the stream cannot take yet waits in the endpoint's bounded write queue, is resent as the stream drains, and `close_stream_write` sends its FIN only behind it. Later writes on the same stream queue behind earlier ones, in order.

When the stream's queued bytes have all been accepted the endpoint emits `EndpointEvent::StreamWriteAccepted { stream, .. }`. If the stream or its connection ends first, or you reset it, it emits `StreamWriteAborted { stream, unsent, .. }` instead. Accepted means accepted locally, never delivered. `node.is_write_pending(stream)` tells whether anything is still queued.

The queue is bounded by the builder's `write_budget` (8 MiB across every stream by default). A payload is admitted whole or refused whole, unsent: `SendError::OverBudget` (retryable once queued bytes drain), `SendError::TooLarge` (bigger than the whole budget: split it), or `SendError::Closing` after a deferred close. Each hands the payload back.

`try_send_stream` is the bare write for applications that manage their own buffers, or that set `write_budget(0)`. It accepts as much as fits and reports the rest as an outcome, so `?` never drops it:

```rust
use minip2p::SendOutcome;

match node.try_send_stream(stream, chunk)? {
    SendOutcome::Accepted => {}
    // A prefix may already have been accepted: only `unsent` is yours.
    // Send it again when `EndpointEvent::StreamWritable` arrives for the stream.
    SendOutcome::Full { unsent } => held = Some(unsent),
}
```

## Close, reset, or abandon

| Operation | Meaning |
| --- | --- |
| `close_stream_write` | Gracefully half-close the local write side; reads may continue. |
| `reset_stream` | Abruptly terminate the stream while keeping terminal stream events visible. |
| `abandon_stream` | Reset the stream, purge buffered matching events, and suppress later matching stream events. |

Stream operations take the `StreamKey`; the peer is the connection's. An operation whose connection has closed or been replaced fails (`SwarmError::StreamNotFound`, or `TransportError::ConnectionNotFound` once nothing names the connection) instead of reaching a stream on the peer's new connection that reuses the ID; `error.is_stream_gone()` is true for both, and false for a write side that is closing.

Use `abandon_stream` when an application has permanently stopped consuming a stream. Calling it again while the abandon/reset is still pending is safe and keeps an ignored stream's events out of the Endpoint event stream. After the stream is fully forgotten, a later call returns an error.

That fixture rewrites wildcard listen addresses to loopback before printing them, the same way [Connect two peers](/docs/rust/connect-peers) does.

## Driver-owned streams

When NAT, pubsub, or discovery drivers are active, they register and consume their own control-plane streams. Those events do not surface as application `StreamData`; handle `EndpointEvent::Nat`, `EndpointEvent::Gossipsub`, or `EndpointEvent::Discovery` instead.
