---
title: Endpoint lifecycle
description: Persist an identity, own the endpoint lifetime on each runtime, and shut down cleanly.
---

A `Minip2p` object owns one endpoint. Its identity, events, pending Promises, and streams all share that lifetime.

## Identity first

The secret key is the node's identity. Generate it once, store the raw 32 bytes somewhere protected, and supply the same bytes on later launches when the node needs a stable peer ID.

<Tabs>
  <Tab title="Node.js">

    ```ts
    import { generateSecretKey, peerIdFromSecretKey } from "@minip2p/node";

    const secretKey = generateSecretKey();
    const peerId = peerIdFromSecretKey(secretKey);
    ```

  </Tab>
  <Tab title="React Native">

    ```ts
    import {
      generateSecretKey,
      peerIdFromSecretKey,
    } from "@minip2p/react-native";

    const secretKey = generateSecretKey();
    const peerId = peerIdFromSecretKey(secretKey);
    ```

  </Tab>
</Tabs>

`peerIdFromSecretKey` derives the public peer identity without starting an endpoint. Treat `secretKey` as credentials: do not log it or transmit it.

- On Node.js, keep it in a file with restrictive permissions or a secret manager, and do not bake it into an image.
- On React Native, keep it in platform-appropriate secure storage, not in ordinary preferences.

## Own the process lifetime

<Badge>Node.js</Badge>

A started endpoint holds a strong event-loop reference. The process will not exit until `close()` is called, so a long-running service should wire shutdown to its termination signals:

```ts
import { Minip2p } from "@minip2p/node";

const endpoint = Minip2p.create({ secretKey });

for (const signal of ["SIGINT", "SIGTERM"] as const) {
  process.once(signal, () => {
    void endpoint.close();
  });
}
```

`close()` never blocks the thread: native disconnects peers and drains for up to 500 ms (`close(timeoutMs)` picks the bound; `0` tears down at once) on its own thread, then releases the event-loop reference, so the process can exit once nothing else keeps it alive.

`Minip2p` also implements `Symbol.asyncDispose` and `Symbol.dispose`. In a scoped tool or test, an `await using` declaration closes the endpoint at scope exit and waits for the drain; `using` starts the close without waiting:

```ts
await using endpoint = Minip2p.create({ secretKey });
```

## Prefer the lifecycle hook

<Badge>React Native</Badge>

`useMinip2p` is the normal component interface. It starts in `starting`, then exposes the endpoint after creation succeeds.

```tsx
const node = useMinip2p(createConfig);

switch (node.status) {
  case "starting":
    return <LoadingView />;
  case "failed":
    return <ErrorView error={node.error} />;
  case "closed":
    return <ClosedView />;
  case "running":
    return <PeerView endpoint={node.endpoint} peerId={node.peerId} />;
}
```

| Status     | Available state                                       |
| ---------- | ----------------------------------------------------- |
| `starting` | Endpoint creation is scheduled after commit.          |
| `running`  | `endpoint`, `peerId`, and the initial `listenAddrs`.  |
| `closed`   | The endpoint closed normally.                         |
| `failed`   | Creation failed or the endpoint stopped unexpectedly. |

Every state also carries an idempotent `close()` callback. Component cleanup unbinds `AppState` and closes the endpoint automatically.

Use `isDriverFailure(node)` to narrow a failed hook state to `DriverFailedError` when the UI needs the machine-readable failure kind.

<Callout type="warning">

Keep the configuration factory pure and stable. React may render a component without committing it; the hook creates the endpoint only after commit.

</Callout>

## Resuming after a pause

A suspended app or a throttled tab stops answering its peers, so its relay connection can die while it is away, sometimes unnoticed until well after it comes back. Call `endpoint.resume()` when the host returns: the relay reservation then recovers at once instead of at its scheduled retry or renewal. A held reservation is renewed, and is reported lost and reacquired if the relay does not answer. Without a relay reservation `resume()` does nothing. Servers never need it.

### Foreground and background

<Badge>React Native</Badge>

The hook watches React Native's `AppState` and calls `resume()` each time the app returns to `active`. The endpoint itself is unchanged while the app is in the background.

If the endpoint is not component-owned, bind and release `AppState` manually:

```ts
import {
  Minip2p,
  bindAppState,
  generateSecretKey,
} from "@minip2p/react-native";

const endpoint = Minip2p.create({
  secretKey: generateSecretKey(),
});
const unbindAppState = bindAppState(endpoint);

// Later, in the owner's cleanup path:
unbindAppState();
endpoint.close();
```

`bindAppState` takes the current state as its starting point, so binding a foreground app does not resume it.

## Close is terminal

`endpoint.close(timeoutMs = 500)` is idempotent: later calls return the same Promise. It:

1. rejects pending Promise operations and drops event listeners;
2. closes owned `Stream` handles;
3. stops the endpoint, letting native disconnect peers and drain for up to `timeoutMs` (`0` tears down at once, best effort);
4. once the drain finishes, invokes each `onClose` observer once and resolves with the same report.

The native bindings (Node.js, React Native) first flush the bytes and FINs they already accepted, within the same deadline; what is still unsent when it passes is lost (QUIC discards it and TCP may abort). The browser ignores `timeoutMs` and ends every WebTransport session at once, without a flush. The report is `{ reason, outcome?, unfinished }`. `reason` is the `EndpointCloseReason`: `"close"`, or `"driverFailed"` (with `error`) when the native driver failed and the endpoint tore down at once. `outcome` (only for `"close"`) is `Drained`, `DeadlineExpired` (running out is not an error), or `Failed` (driving the transports failed and ended the drain early). `unfinished` lists the peers whose connections were still tracked when the drain ended; empty means no tracked teardown remains, not that peers acknowledged it. The Promise never rejects.

```ts
endpoint.onClose((report) => {
  if (report.reason === "driverFailed") {
    console.error(report.error.kind, report.error.message);
  }
});

const report = await endpoint.close(1_000);
if (report.reason === "close" && report.outcome !== "Drained") {
  console.warn("closed with unfinished peers", report.unfinished);
}
```
