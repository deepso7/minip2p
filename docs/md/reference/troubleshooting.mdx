---
title: Troubleshooting
description: Diagnose Rust and React Native connection, stream, lifecycle, discovery, and event problems by symptom.
---

Start from the observable symptom. The Rust API returns synchronous errors
directly and reports later runtime or protocol failures through events.

## Common problems

| Symptom | Likely cause | Corrective action |
| --- | --- | --- |
| `PeerAddr` fails to parse | Missing or non-terminal `/p2p/<peer-id>` | Copy the complete peer address, including its terminal identity. |
| An address parses but dialing fails immediately | Wrong shape, or that transport was not compiled/bound | Use a host plus `/udp/<port>/quic-v1` or `/tcp/<port>`, and enable/bind that transport. |
| A remote peer cannot dial a printed wildcard address | `0.0.0.0` or `::` is a bind wildcard | Advertise a real interface/public address or a relay circuit address. |
| `ConnectionEstablished` appears but the app protocol cannot open | Identify has not completed | Wait for `PeerReady` before `open_stream`. |
| `ProtocolNotRegistered` | The local endpoint never registered the ID | Add `.protocol("/app/name/1.0.0")` on the builder or call `add_protocol`. |
| `ReservedProtocol` | The app tried to register Identify or Ping | Choose an application-owned, versioned protocol ID. |
| `RemoteDoesNotSupport` | Identify completed and the remote did not advertise the protocol | Register the same protocol version on both peers. |
| NAT, pubsub, discovery, or mDNS reports “not enabled” | Cargo compiled the API but the builder did not activate the driver | Add the corresponding builder activation from the feature matrix. |
| AutoNAT reports reachability but `connect` has no relay path | Only `.autonat_server(...)` was configured | Add a Circuit Relay v2 server with `.relay(...)` or `NatConfig::relays`. |
| No relay reservation appears | Relay unreachable, incompatible, or policy does not currently reserve | Check the relay address, connection events, reachability state, and `ReservationPolicy`. |
| Hole punching fails | UDP paths or observed addresses are unusable | Keep the relay path, inspect `HolePunchFailed`, and verify both sides keep driving. |
| Pubsub receives no local copy | Self-delivery is intentionally disabled | Apply the local action directly and treat pubsub as remote delivery. |
| Unsigned pubsub message is rejected | `allow_unsigned` defaults to `false` | Enable it only when the remote intentionally sends unsigned application messages. |
| Discovery rejects an unsigned beacon | Discovery always requires signed beacons | Fix the remote discovery publisher; application `allow_unsigned` does not relax discovery. |
| Unsubscribing the discovery topic fails | The topic is driver-owned | Leave its lifecycle to discovery; use a separate topic for application messages. |
| mDNS discovers no local peers | The network blocks multicast, the interfaces do not share a link, or `.mdns()` was not activated | Confirm both endpoints keep driving, use a multicast-capable local network, and activate mDNS on both peers. |
| A quiet connection closes | Idle timeout on the transport, peer, or something in between | Send app traffic or Ping often enough for your path. |
| A focused wait returns `EventBacklogExceeded` | Too many unrelated events were preserved during the wait | Drain ordinary events with `poll` or `next_event`, handle the busy source, then retry. |

## Event response cheat sheet

| Event | Typical response |
| --- | --- |
| `Event::PeerReady` | Open application streams or record the peer as usable. |
| `Event::StreamReady` | Attach the stream to the matching protocol handler; outbound streams may now write. |
| `Event::StreamData` | Feed bytes into the application's framing/decoder. |
| `Event::StreamRemoteWriteClosed` | Finish decoding and optionally half-close the local write side. |
| `Event::Error` | Log structured context and decide whether the affected operation should retry. |
| `NatEvent::PathEstablished` | Begin traffic on the peer's ordinary stream APIs. |
| `NatEvent::PathUpgraded` | Update metrics/UI; stream APIs continue to address the same peer. |
| `NatEvent::ConnectFailed` | Inspect `NatError`, correct infrastructure or candidates, then start a new attempt. |
| `PubsubEvent::OutboundFailure` | Record or retry at the application layer if delivery semantics require it. |
| `DiscoveryEvent::DialFailed` | Keep discovery running; unchanged beacons retry after configured backoff. |

## Debug in layers

<Steps>
  <Step title="Confirm the endpoint is being driven">
    Both peers must keep calling `poll`, `next_event`, or focused waits.
  </Step>
  <Step title="Confirm identity and address shape">
    Log the complete `PeerAddr`, local `PeerId`, and relevant bind addresses.
  </Step>
  <Step title="Confirm the readiness milestone">
    Distinguish a finished, authenticated connection from `PeerReady`.
  </Step>
  <Step title="Confirm feature activation">
    Check both the Cargo feature and the builder method.
  </Step>
  <Step title="Inspect the right event queue">
    Driver-owned NAT, pubsub, and discovery work appears in their focused
    queues, not as raw application stream events.
  </Step>
</Steps>

For exhaustive variants and fields, generate local
[rustdoc](/reference/feature-matrix#exhaustive-api-docs).

## React Native

React Native errors are public classes re-exported from
`@minip2p/react-native`. Use `instanceof` for application recovery and inspect
typed `kind` fields for diagnostics.

| Symptom | Likely cause | Corrective action |
| --- | --- | --- |
| The package cannot load in Expo Go | Expo Go does not contain the minip2p TurboModule or native Rust libraries | Use `expo-dev-client`, run `expo prebuild`, then `expo run:ios` or `expo run:android`. |
| The native module is missing after installation | The development build predates the package or native autolinking did not run | Run `expo prebuild` and rebuild with `expo run:ios` or `expo run:android`; for bare React Native, clean and rebuild the native project. |
| The hook remains `starting` briefly | Endpoint construction is intentionally deferred until the component commits | Render the starting state; read `endpoint` only when `status === "running"`. |
| A hook endpoint changes polling behavior in the background | `useMinip2p` mirrors `AppState` by design | Keep the hook mounted; it resumes foreground behavior when AppState becomes `active`. |
| A manually created endpoint stays in foreground mode | Nothing is forwarding React Native `AppState` | Call `bindAppState(endpoint)` and invoke its unsubscribe before closing. |
| A Promise rejects with `TimeoutError` | No matching result arrived within `timeoutMs` | Confirm the peer and infrastructure, then choose a timeout appropriate to the UI. Avoid `timeoutMs: 0` unless an unbounded wait is intentional. |
| A Promise rejects with `AbortError` | Its `AbortSignal` fired, or a split-phase attempt was cancelled | Treat cancellation as expected control flow; create a new controller for a retry. |
| `waitPeerReady` rejects with `PeerDisconnectedError` | The last connection closed before Identify completed | Reconnect, keep both drivers alive, and wait again. |
| `openStream` rejects with `OpenStreamError` | The peer is not ready, the protocol is unsupported, or negotiation failed | Wait for `peerReady`, inspect `peerInfo(peerId)?.protocols`, and register the same version on both peers. |
| An inbound stream closes immediately | No named `"stream"` handler or waiter claimed its live handle | Subscribe to `endpoint.on("stream", ...)`; catch-all `inboundStream` is metadata only. |
| `read()` rejects after adding a `data` handler | Pull and flowing modes were mixed | Pick one read mode for the stream's entire lifetime. |
| `dataOverflow` fires | Pull-mode bytes accumulated faster than the app consumed them | Reset or abandon the stream and recover at the application protocol layer. |
| `BackpressureError` is thrown by `publish` | The bounded native pubsub queue is full | Slow or batch publishers and retry only according to application delivery rules. |
| An unsigned message has an unexpected peer ID | `allowUnsigned: true` accepts unauthenticated sender claims | Treat both `fromPeerId` and payload as attacker-controlled whenever `signed` is false. |
| mDNS finds no peers on iOS or Android | Host permissions are missing, multicast is blocked, or peers do not share a link | Add the documented local-network/multicast configuration and test on a multicast-capable network. |
| AutoNAT reports state but `connect` cannot relay | `autonatServers` probes reachability but does not provide traversal | Add a reachable direct QUIC or TCP relay peer address to `relays`. |
| `queueOverflow` fires | JavaScript did not drain the bounded native event queue quickly enough | Refresh `connectedPeers`, `knownPeers`, paths, reachability, and reservation state; reduce slow event handlers. |
| The hook enters `failed` | The native driver stopped unexpectedly | Use `isDriverFailure(state)`, log its typed kind, recreate at an application-owned boundary, and do not reuse the closed endpoint. |

See the [React Native API reference](/reference/react-native-api#public-errors)
for the complete public error taxonomy.
