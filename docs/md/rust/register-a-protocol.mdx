---
title: Register a protocol
description: Register an application protocol, negotiate streams, exchange bytes, and close or abandon stream state on purpose.
---

Application protocols use libp2p multistream-select negotiation over an authenticated connection. Both peers must register the same versioned protocol ID. `connect` first; open streams once the peer is connected. Waiting for [`PeerReady`](/rust/concepts#connection-readiness) is optional when you want Identify's advertised protocols before opening.

```rust
const ECHO_PROTOCOL: &str = "/my-app/echo/1.0.0";

let mut node = minip2p::Endpoint::builder()
    .protocol(ECHO_PROTOCOL)
    .listen_default()?
    .bind()?;
```

You can also call `add_protocol` after binding. Registration affects inbound and outbound negotiation.

<Callout type="warning">

`/ipfs/id/1.0.0` and `/ipfs/ping/1.0.0` are owned by the endpoint. Registering an ID in `RESERVED_PROTOCOL_IDS` fails with `minip2p::Error::Swarm(minip2p::SwarmError::ReservedProtocol { .. })`.

</Callout>

## Open an outbound stream

Once the attempt settles `Connected`, request a stream. A protocol both peers registered does not need to wait for Identify; match `PeerReady` first only if you want unsupported protocols to fail early with `RemoteDoesNotSupport`.

`open_stream` starts negotiation and returns the connection and the allocated stream ID. Stream IDs are unique only per connection, so every stream operation takes both. Wait for the matching `EndpointEvent::StreamReady` before writing:

```rust
use std::time::{Duration, Instant};

use minip2p::{ConnectOutcome, EndpointEvent, EndpointWaitOutcome};

let peer_id = target.peer_id().clone();
let connect_id = node.connect(target)?;
let mut stream = None;
let deadline = Instant::now() + Duration::from_secs(10);

loop {
    let event = match node.wait(deadline)? {
        EndpointWaitOutcome::Event(event) => event,
        // Another thread woke the wait; nothing to service here.
        EndpointWaitOutcome::Interrupted => continue,
        EndpointWaitOutcome::Deadline => return Err("stream negotiation timed out".into()),
    };

    match event {
        EndpointEvent::ConnectSettled {
            connect_id: id,
            outcome,
            ..
        } if id == connect_id => match outcome {
            ConnectOutcome::Connected { .. } => {
                stream = Some(node.open_stream(&peer_id, ECHO_PROTOCOL)?);
            }
            other => return Err(format!("connect failed: {other:?}").into()),
        },
        EndpointEvent::StreamReady {
            peer_id: peer,
            conn_id,
            stream_id: ready,
            protocol_id,
            ..
        } if peer == peer_id && Some((conn_id, ready)) == stream && protocol_id == ECHO_PROTOCOL => {
            node.send_stream(&peer_id, conn_id, ready, b"hello".to_vec())?;
            node.close_stream_write(&peer_id, conn_id, ready)?;
            break;
        }
        other => handle_other_event(other),
    }
}
```

Put this match in the application's ordinary event dispatcher. Do not discard events for other peers or streams while waiting for negotiation.

QUIC is a byte stream: writes can be fragmented or coalesced. Add framing when one application message must be distinguishable from the next.

## Accept an inbound stream

Inbound negotiation produces the same `StreamReady` event with `initiated_locally: false`. Track accepted streams by peer, connection, and stream ID so later `StreamData` can be routed to the correct handler:

```rust
use std::collections::HashSet;

use minip2p::{ConnectionId, EndpointEvent, PeerId, StreamId};

let mut echo_streams: HashSet<(PeerId, ConnectionId, StreamId)> = HashSet::new();

match event {
    EndpointEvent::StreamReady {
        peer_id,
        conn_id,
        stream_id,
        protocol_id,
        initiated_locally: false,
    } if protocol_id == ECHO_PROTOCOL => {
        echo_streams.insert((peer_id, conn_id, stream_id));
    }
    EndpointEvent::StreamData {
        peer_id,
        conn_id,
        stream_id,
        data,
    } if echo_streams.contains(&(peer_id.clone(), conn_id, stream_id)) => {
        node.send_stream(&peer_id, conn_id, stream_id, data)?;
        node.close_stream_write(&peer_id, conn_id, stream_id)?;
        echo_streams.remove(&(peer_id, conn_id, stream_id));
    }
    _ => {}
}
```

## Write backpressure

`send_stream` accepts anything that converts into `Bytes` and queues as much as the stream can take. When not every byte fit it returns `Error::Full` with the exact unsent tail. That is backpressure, not a failure: keep the tail and send it again when `EndpointEvent::StreamWritable` arrives for the stream. While the stream stays open and the writer keeps resending on `StreamWritable`, a large write completes, and a slow reader slows the writer down instead of tearing the connection down.

```rust
use minip2p::{Bytes, EndpointEvent, Error};

// The unsent tail of the last write, if the stream was full.
let mut held: Option<Bytes> = None;

// Writing: take the next chunk only while nothing is held, so no chunk is
// pulled and lost while an earlier tail waits.
if held.is_none()
    && let Some(chunk) = next_chunk()
{
    match node.send_stream(&peer_id, conn_id, stream_id, chunk) {
        Ok(()) => {}
        Err(Error::Full { unsent, .. }) => held = Some(unsent),
        Err(error) => return Err(error.into()),
    }
}

// In the event loop: resend the tail once the stream is writable.
if let EndpointEvent::StreamWritable { conn_id: c, stream_id: s, .. } = &event
    && (*c, *s) == (conn_id, stream_id)
    && let Some(tail) = held.take()
{
    match node.send_stream(&peer_id, conn_id, stream_id, tail) {
        Ok(()) => {} // Fully accepted; the next chunk may go.
        Err(Error::Full { unsent, .. }) => held = Some(unsent),
        Err(error) => return Err(error.into()),
    }
}
```

Close the write side only once the held tail has gone out. `StreamWritable` never fires after the write side ended; `StreamWriteStopped`, `StreamClosed`, or the connection closing mean the tail should be dropped.

## Close, reset, or abandon

| Operation | Meaning |
| --- | --- |
| `close_stream_write` | Gracefully half-close the local write side; reads may continue. |
| `reset_stream` | Abruptly terminate the stream while keeping terminal stream events visible. |
| `abandon_stream` | Reset the stream, purge buffered matching events, and suppress later matching stream events. |

An operation whose connection has closed or been replaced fails with `SwarmError::StreamNotFound` instead of reaching a stream on the peer's new connection that reuses the ID.

Use `abandon_stream` when an application has permanently stopped consuming a stream. Calling it again while the abandon/reset is still pending is safe and keeps an ignored stream's events out of the Endpoint event stream. After the stream is fully forgotten, a later call returns an error.

The complete two-peer echo used in CI lives in [`docs/snippets/custom-stream`](https://github.com/deepso7/minip2p/tree/main/docs/snippets/custom-stream). That fixture rewrites wildcard listen addresses to loopback before printing them, the same way [Connect two peers](/rust/connect-peers) does.

## Driver-owned streams

When NAT, pubsub, or discovery drivers are active, they register and consume their own control-plane streams. Those events do not surface as application `StreamData`; handle `EndpointEvent::Nat`, `EndpointEvent::Gossipsub`, or `EndpointEvent::Discovery` instead.
